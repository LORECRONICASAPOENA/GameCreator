## Problema e diagnóstico

A implementação anterior aceitava mensagens com `event.origin === "null"` sem autenticar a janela de origem e transportava payloads pelo canal global `postMessage`. Isso era necessário para a integração local `file://`, mas não oferecia autenticação suficiente.

A primeira tentativa de hardening, run [#41905233755](https://github.com/LORECRONICASAPOENA/GameCreator/actions/runs/41905233755), falhou no teste de navegador. O artefato de diagnóstico mostrou que as operações de biblioteca chegaram ao host, mas `BRIDGETRACE` permaneceu vazio: a janela filha não enviou o handshake `ready`. O atributo `iframe.name` não foi suficiente para propagar o nonce no harness.

## Correção aplicada

1. Nonce criptográfico de 256 bits, gerado por `crypto.getRandomValues`.
2. Allowlist explícita de `WindowProxy` autorizada pelo host, vinculada ao nonce.
3. Para origem não opaca, validação exata de `event.origin`; para `file://`, aceitação somente com source+nonce previamente autorizados.
4. Handshake global mínimo; transferência de `MessagePort` por `MessageChannel`.
5. Payloads, ações e respostas trafegam exclusivamente pelo canal privado.
6. Nonce passado no fragmento `#apoenaBridgeToken`, removido após leitura; `window.name` mantido como fallback.
7. Teste Node corrigido para simular as direções de `postMessage` e o suporte a `URLSearchParams`.
8. Harness de navegador atualizado para autorizar o iframe antes de carregar o Criador Modular.

O wildcard `postMessage("*")` permanece somente na transferência inicial do `MessagePort` quando a origem é opaca, pois o navegador não oferece target origin específico para `file://`. Essa mensagem contém apenas o token e o canal; nenhum payload do projeto trafega por wildcard.
